## `> how to contribute`

New to open source? No problem. These steps work for **every repository** on my profile, and for any other GitHub project too.

**1. Fork**: open the repo and click **Fork** (top right). You get your own copy.

**2. Clone**: download your copy to your computer.
```bash
git clone https://github.com/<your-username>/<repo-name>.git
cd <repo-name>
```

**3. Branch**: never work on `main`. Make a new branch named after your change.
```bash
git checkout -b fix/short-description
```

**4. Set up and change**: follow the project's own README to install and run it, then make your change.
```bash
# Next.js / React projects
npm install && cp .env.example .env.local && npm run dev

# Django / Flask projects
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt
```

**5. Commit**: save your work with a clear message.
```bash
git add .
git commit -m "fix: describe what you changed"
```

**6. Push**
```bash
git push origin fix/short-description
```

**7. Open a Pull Request**: go to your fork on GitHub, click **Compare & pull request**, explain *what* and *why*, then submit. I review every PR.

<details>
<summary><b>Keep your fork up to date</b></summary>

```bash
git remote add upstream https://github.com/prathammalkan/<repo-name>.git
git fetch upstream
git checkout main
git merge upstream/main
```
</details>

<details>
<summary><b>Good first contributions</b></summary>

- Fix typos or improve documentation
- Report a bug: **Issues → New issue** (add steps to reproduce and a screenshot)
- Suggest a feature in an issue *before* building it
- Improve accessibility, performance or test coverage
</details>

**Ground rules:** be kind, keep one PR to one change, never commit secrets (`.env` files), and test before you push.
